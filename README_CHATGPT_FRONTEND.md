# 使用方式：ChatGPT 是唯一前台

你不需要打开 GitHub Pages，也不需要在网页里看推荐号码。

后台由 GitHub Actions 负责：
- 08:37 数据同步、研究员模式；核验数据后可冻结当日正式推荐
- 12:07至15:45多次重试，包含15:30；已有冻结不重选
- 18:45截止前恢复；23:07、23:37开奖后同步和复盘

调度采用显式UTC，完整计划及延迟限制见 GITHUB_ACTIONS_DEPLOY.md。

后台每次运行后只生成 `bridge/*.json` 机器文件。ChatGPT 定时任务在稍后读取这些文件，并在 ChatGPT 对话中推送号码、复盘与模型变化。

首次部署后，把仓库 URL 发给 ChatGPT 一次，用于绑定 raw JSON 地址。之后用户交互均留在 ChatGPT。

双色球16:00任务使用 [完整任务提示词](CHATGPT_SSQ_TASK_PROMPT.md)。先解析同一 `main` 提交中的 `bridge/ssq.json` 和 `bridge/latest.json`；以 `publication` / `publications.ssq` 的正式记录核验结果决定是否发布。桥接运行时间和推荐有效期分开判断：当天14:06已冻结的有效记录，不应仅因缺少15:30以后运行或桥接文件约两小时前生成而被阻断。

开奖日、休市、目标日期、冻结校验、号码合法性、基准数据一致性和20:00发布截止仍是硬性条件。`BRIDGE_STALE`、主接口403或另一彩种研究任务异常应如实披露，不能自行推导为双色球正式记录失效；存在具体数据冲突或安全校验失败时仍须停止发布。

每次正式推送保留 `dedupe_key`、`target_issue_key`、`prediction_id` 和 `freeze_sha256`，以后按正式推送记录去重。复盘记录不代表推送回执。任务历史缺失时应明确报告“去重状态无法确认”，不得虚构已发送状态。当前ChatGPT对话回执不能提供跨系统原子确认，因此不能承诺严格的恰好一次投递。
