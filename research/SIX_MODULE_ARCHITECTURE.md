# 彩票研究助理：六模块统一架构（v1.1）

> 本文件是项目总纲。用户原先确认的六块能力全部保留；`ssq-fusion` / `dlt-fusion` 的可取部分只作为增强，不替代原架构。

## 模块1：每日数据研究（Data Intelligence）

目标：确保所有研究建立在真实、完整、可追溯的数据上。

- 官方来源优先，失败时 fail-closed，不用模拟数据替代。
- 双色球与大乐透独立数据表、独立规则、独立模型状态。
- 保存全历史，并生成 10/20/30/50/100/300/500 期滚动窗口。
- 校验期号、日期、号码范围、号码数量、重复号码、数据缺口与重复记录。
- 所有抓取、修复、版本变化写入 evolution log。

## 模块2：规律实验室（Pattern Laboratory）

目标：把“规律”变成可验证的变量，而不是互相冲突的经验铁律。

### 2.1 从 ssq-fusion / dlt-fusion 吸收的精华

保留并统一：

- 多窗口频率与共识：10/20/30/50/100期；
- 频率 z-score；
- 当前遗漏、理论遗漏比、遗漏 z-score；
- 指数衰减频率与短长趋势；
- 重号、邻号、跟随/转移关系；
- 和值、跨度、奇偶、大小、三区、012路；
- 连号、同尾、质合、AC值；
- 主区/副区分离，双色球蓝球、大乐透后区独立分析；
- 推荐留痕、开奖对奖、随机基线、Wilson/二项思想、自学习闭环。

### 2.2 冲突消解原则

以下说法不得作为并列策略直接投票：

- “追热” vs “追冷”；
- “遗漏回补” vs “持续冷却”；
- “避开上期号” vs “重号延续”；
- “邻号优先” vs “孤号优先”；
- “均值回归” vs “趋势延续”。

统一处理方式：全部转成**无方向的可学习特征**。模型允许学到正系数、负系数或零贡献；只有样本外结果决定它是否保留。

### 2.3 结构指标的定位

和值、跨度、奇偶、大小、三区、012、AC、连号、同尾等用于描述“组合形态”，不直接解释为下一期概率。生产阶段只允许作为低权重 soft tie-breaker，禁止硬过滤导致把真实开奖号提前删除。

## 模块3：模型动物园（Model Zoo）

目标：模型可以多样，但治理标准只有一套。

### 3.1 生产锚点

- Uniform Random Baseline：零模型；
- Empirical Bayes：长期频率的保守收缩；
- Regularized Logistic Regression：解释性线性模型；
- Histogram Gradient Boosting：非线性交互模型；
- Dynamic Ensemble：只按样本外表现融合。

### 3.2 挑战者池

XGBoost、LightGBM、CatBoost、HMM、LSTM、GRU、Transformer、强化学习、遗传算法、蒙特卡洛搜索、其他 GitHub 新模型均先进入挑战者池。

任何“特别的彩票AI方法”都必须满足：

1. 同一期所有号码按完整期次切分，禁止行级随机 train/test；
2. 所有特征在预测 t 期时只能用 `< t` 的数据；
3. 最终 holdout 不参与调参；
4. 与 Uniform / Bayes / Logistic 同协议比较；
5. 多模型/多特征试验要防 multiple testing；
6. 不能因为一次高命中就晋级。

## 模块4：每日进化引擎（Evolution Engine）

目标：开奖后学习，但不追着噪声跑。

- 逐模型记录 Brier、LogLoss、Top-K Recall、Mean Hits、校准度和稳定性。
- 同时观察 10/30/50/100 期滚动表现和长期 holdout。
- 模型权重只能由样本外表现改变。
- 单期命中只记账，不触发重大调权。
- 新模型先 shadow/challenger；连续验证后才小权重上线，再逐步晋级。
- 退化模型自动降权或退役，但保留历史版本以便回滚。

## 模块5：开奖前单一最终输出（Decision Output）

目标：复杂研究在后台完成，用户只收到一套清晰结果。

每个开奖日只输出：

- 当期一组主推荐号码；
- 当前模型版本；
- 主/副区核心权重；
- 本期相对上一版本的变化；
- 简洁的可审计依据。

推荐分数是模型内部排序分，不表示实际中奖概率。候选组合由统一概率层生成，结构层仅作轻度排序调整。

## 模块6：开奖后复盘与进化（Post-Draw Review）

目标：让每一次真实开奖都成为新的样本，而不是事后找理由。

固定流程：

`开奖前冻结预测 → 官方结果入库 → 对奖 → 分模型归因 → 滚动回测更新 → 稳定性/显著性检查 → 调权/不调权 → 版本留痕`

必须回答：

- 主区、副区分别命中多少；
- 哪些模型/特征有贡献，哪些只是巧合；
- 与 Uniform 基线的差异是否持续；
- 是否存在数据泄漏、过拟合、多重比较假阳性；
- 是否需要保持、降权、退役、晋级或回滚。

## 跨模块：研究员模式（Researcher Mode）

研究员模式不是第7个平行预测器，而是六模块的“研发部门”。每日扫描 GitHub、论文、公开项目与方法论：

`发现 → 提炼假设 → 注册候选 → 实现 → walk-forward → untouched holdout → 基线比较 → 审计 → 晋级/淘汰`

它可以让系统持续学习，但**不能绕过模块3/4的验证门槛直接改变模块5的推荐**。
